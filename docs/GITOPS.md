# GitOps Deployment (Terraform → Kubernetes → ArgoCD)

This document describes the automated deployment of Jambo on **DigitalOcean
DOKS** and **Amazon EKS** using Terraform, ArgoCD and the External Secrets
Operator (ESO). **No Ansible.**

## The stack, by layer

| Tool | Role |
|------|------|
| **Terraform** ([`terraform/`](../terraform/)) | Provisions the cluster, node pools, `jambo-sc` StorageClass, managed Postgres/Redis (prod), DNS, platform add-ons, and ArgoCD itself (Helm + repo credential + app-of-apps seed). |
| **Kubernetes** ([`k8s/`](../k8s/)) | Runs the SaaS workloads and observability stack. |
| **ArgoCD** ([`argocd/`](../argocd/)) | Reconciles Git (single source of truth) with the cluster. |
| **HCP Vault + ESO** | Provides secrets (`jambo-secrets`, `monitoring-nginx-secrets`, `alertmanager-secrets`). |

## Environments & branches

| Environment | Branch | Overlay | Postgres / Redis | RabbitMQ |
|-------------|--------|---------|------------------|----------|
| staging | `main` | `k8s/overlays/staging` | in-cluster | Cluster Operator |
| prod | `prod` | `k8s/overlays/prod` | managed (Terraform) | Cluster Operator |

`main` additionally deploys to **Coolify** (Docker Compose) via the existing
webhook path; `prod` deploys to Kubernetes via GitOps.

## End-to-end flow

1. **Provision infrastructure (Terraform).**
   `cd terraform/environments/<cloud>/<env> && terraform init && terraform apply`.
   This creates the cluster, `jambo-sc`, managed data services (prod), DNS, and
   installs ingress-nginx, cert-manager, external-dns, ESO, metrics-server, the
   RabbitMQ Cluster Operator, and **ArgoCD** (Helm release, the `jambo-repo`
   repository credential, and the `jambo-apps` seed). See
   [`argocd/README.md`](../argocd/README.md).
2. **Populate HCP Vault** with the secret keys documented in
   [`k8s/base/secret.yaml.example`](../k8s/base/secret.yaml.example), including
   `DATABASE_URL`/`REDIS_URL` (managed prod) and `RABBITMQ_URL`.
3. **ArgoCD reconciles** `argocd/apps` (AppProject + ApplicationSet) and the
   workloads under `k8s/overlays/<env>`. Verify with `argocd app list`.
4. **Push to `prod`.** CI builds + pushes GHCR images (`sha-<sha>`), pins the tag
   in `k8s/overlays/prod/kustomization.yaml`, and pushes. ArgoCD detects the
   change and syncs the cluster.

## Day-to-day GitOps workflow

The GitOps system is launched by a single `terraform apply` and thereafter
operates by pushing to Git. Recurring cases:

**A. Deploy a new app image (the common case).**
1. Merge to `main` (staging) or `prod` (prod).
2. [`deploy.yml`](../.github/workflows/deploy.yml) builds + pushes GHCR
   `sha-<sha>` and pins the tag in the overlay.
3. ArgoCD auto-syncs. Verify: `argocd app get jambo-prod`,
   `kubectl -n jambo get pods`.

**B. Change a manifest / config (no new image).**
1. Edit under `k8s/base/` or `k8s/overlays/<env>/`.
2. Commit + push to the env branch.
3. ArgoCD auto-syncs (selfHeal + prune). No CI run needed.

**C. Add a new component (e.g. a new Deployment).**
1. Add the manifest to `k8s/base/` and reference it in
   [`k8s/base/kustomization.yaml`](../k8s/base/kustomization.yaml).
2. Add any env-specific patch to the overlay.
3. Push to the env branch; ArgoCD applies it.

**D. Add a new environment (e.g. a `dev` env).**
1. Create `k8s/overlays/dev/` (copy of staging, adjust config).
2. Add an element to the list generator in
   [`argocd/apps/applicationset.yaml`](../argocd/apps/applicationset.yaml).
3. Add a `terraform/environments/<cloud>/dev/` state + a `platform` call with
   `argocd_app_of_apps_target_revision = "dev"`.
4. Push; the ApplicationSet generates `jambo-dev` and ArgoCD syncs it.

**E. Upgrade ArgoCD itself.**
1. Bump `argocd_version` in the platform module.
2. `terraform apply` (or CI) — Terraform upgrades the Helm release.
   ArgoCD-managed apps are untouched.

**F. Rotate the GitHub PAT.**
1. Update `TF_VAR_argocd_repo_password` / the CI secret.
2. `terraform apply` updates the `jambo-repo` Kubernetes secret.

**G. Drift / out-of-sync troubleshooting.**
- `argocd app get jambo-prod`, `argocd app diff`, `argocd app sync`.
- Check the AppProject allows the destination namespace
  ([`jambo-project.yaml`](../argocd/apps/jambo-project.yaml)).

## Secrets (HCP Vault via ESO)

- `k8s/overlays/{staging,prod}/external-secret.yaml` declares a `SecretStore`
  (`hcp-vault`) and three `ExternalSecret`s that materialize the Kubernetes
  Secrets from Vault KV (path `secret/jambo`).
- The `server` URL is a placeholder — patch it per environment.
- RabbitMQ credentials are generated by the Cluster Operator into the
  `rabbitmq-default-user` Secret; construct `RABBITMQ_URL`
  (`amqp://<user>:<pass>@rabbitmq:5672/%2f`) from it and store it in Vault once
  during bootstrap.

## Cross-cloud notes

- Both clouds use **ingress-nginx** and a Terraform-managed StorageClass
  **`jambo-sc`** (`do-block-storage` on DOKS, `gp3` on EKS). PVCs are pinned to
  it via the staging/prod overlays.
- EKS needs the `aws-ebs-csi-driver` addon (declared in the EKS environment) and
  IRSA roles for external-dns/cert-manager (`terraform/modules/iam`). DOKS uses
  static credentials, so the `iam` module is unused.

## Known caveats

- Scaling `backend` beyond 1 replica requires verifying Redis Pub/Sub
  sharded-subscriber fan-out semantics (see `k8s/base/hpa.yaml`).
- The observability stack (Prometheus/Loki/Tempo/Grafana/Alertmanager) runs
  in-cluster; consider moving to managed/external offerings to reduce cost.
